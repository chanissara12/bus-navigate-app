# bus-navigate-app

แอปส่วนตัวสำหรับ **ตอนยืนอยู่ที่ป้ายรถเมล์** ในกรุงเทพฯ ทำให้สายรถเมล์ "อ่านออก"

> ตอนนี้ repo นี้ยังมีแต่ **แผนและการตัดสินใจ ยังไม่มีโค้ดของแอปจริง**

## ปัญหาที่แก้

เคสจริงสองเคสที่เป็นต้นเรื่อง

1. **ขึ้นผิดคัน** — ขึ้นรถไปแล้วโดยเข้าใจว่าเป็นสายที่ใช่ แล้วไม่รู้ว่าสายนั้นผ่านที่ไหนบ้าง
2. **รอเก้อ** — รอสายที่ถูกต้อง แต่รถไม่มาสักที จนไม่รู้ว่าควรทำยังไงต่อ

ทั้งสองเคสเกิด **ที่ป้ายรถเมล์** ไม่ใช่ที่บ้านก่อนออกเดินทาง นี่จึงไม่ใช่แอปวางแผนการเดินทาง —
ViaBus กับ Google Maps ทำไปแล้ว จุดที่มันตอบไม่ได้คือ **"คันที่ฉันนั่งอยู่จะพาฉันไปไหน"**
ซึ่งเป็นคำถามที่ตั้งต้นจาก **สาย** ไม่ใช่จาก **ปลายทาง**

ตัวเลขที่อธิบายปัญหาได้ดีที่สุด: ที่ป้ายอนุสาวรีย์ชัยสมรภูมิ (เกาะพญาไท) มีรถเมล์จอด
**26 สาย** และมีแค่ **8 สาย** ที่ไปถึงสยาม — เดาแล้วถูก 1 ใน 3

## สถานะ

แผนทั้งหมดอยู่ที่ [`.wayfinder/MAP.md`](.wayfinder/MAP.md) ซึ่งเป็นแผนที่นำทางของโปรเจกต์
รายละเอียดของแต่ละการตัดสินใจอยู่ใน [`.wayfinder/tickets/`](.wayfinder/tickets/)
และรายงานค้นคว้าที่รองรับอยู่ใน [`.wayfinder/research/`](.wayfinder/research/)

ตัดสินใจไปแล้ว 10 ข้อ ที่สำคัญคือ

- ข้อมูลสายและป้ายใช้ **ฟีด Namtang** ของ สนข. — ยืนยันแล้วว่ามีจริงและอัปเดตทุกวัน
- **ตำแหน่งรถแบบ real-time หาไม่ได้เลย** ไม่ว่าทางไหน ต้องออกแบบโดยไม่พึ่งมัน
- บอกทิศด้วย **ข้อความหน้ารถ** (`trip_headsign`) ซึ่งต่างกันครบทั้ง 817 สายสองทิศ
- ขอบเขตคือ **ขสมก. + ไทยสมายล์บัส 373 สาย** ซึ่งทำให้ปัญหาป้ายไม่มีชื่อ 46% หายไปทั้งหมด
- หน้าจอหลักคือ **รายการสายที่ขึ้นได้ + ช่องกดเลขสายปักบนสุด** และ **แผนที่แบบออฟไลน์ล้วน**

ยังเหลือการตัดสินใจเรื่องวิธีค้นจากปลายทาง และวิธีเก็บข้อมูลลงเครื่อง

## ต้นแบบ

ต้นแบบหน้าจอ (ใช้แล้วทิ้ง ไฟล์เดียวจบ) อยู่บน branch `prototype/wf-010-standing-at-the-stop`
ไม่ได้อยู่บน main

```bash
git checkout prototype/wf-010-standing-at-the-stop -- prototypes
```

แล้วเปิด `prototypes/wf-010-standing-at-the-stop/index.html` ด้วยเบราว์เซอร์ได้เลย
มี 4 แบบให้เทียบ สลับด้วยปุ่มลูกศรที่แถบล่างหรือปุ่ม `←` `→`
