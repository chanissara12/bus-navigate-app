# ป้ายไร้ชื่อในฟีด Namtang — ผลการวัด

วิเคราะห์จากฟีด GTFS ที่ดาวน์โหลดไว้ (`feed_info.feed_version = 20260919`) ด้วยสคริปต์ throwaway ใน scratchpad
ทุกตัวเลขในรายงานนี้นับจากไฟล์จริง ไม่ใช่ประมาณ

## Bottom line

- **ยืนยัน 46% แต่ตัวเลขนี้หลอก** — 7,930/17,078 = **46.43%** ถูกต้อง แต่ปัญหา **ไม่ได้กระจายทั่ว** มันกระจุกอยู่ที่ผู้ให้บริการเดียว
- **ป้ายของ ขสมก. และ Thai Smile Bus ไม่มีป้ายไร้ชื่อแม้แต่ป้ายเดียว — 0 จาก 4,879 และ 0 จาก 5,349** ป้ายไร้ชื่อ 7,929 จาก 7,930 จุดอยู่บนสายที่ขึ้นทะเบียนกับ **DLT (กรมการขนส่งทางบก)** ซึ่งคือรถร่วมฯ/สายหมวด 1–4 ที่ สนข. ดิจิไทซ์ด้วยการลากเส้นบนแผนที่ (จึงได้ชื่อว่า "visual stop")
- **ในกรุงเทพชั้นใน (รัศมี 10 กม. จากสยาม) ป้ายไร้ชื่อเหลือ 17.2%** (554/3,213) และในนั้น **ทั้ง 554 จุดเป็นป้าย DLT ล้วน** ส่วนที่แย่ที่สุดคือปริมณฑล 78.5% และต่างจังหวัด 0% (เพราะต่างจังหวัดในฟีดเป็นสาย บขส./สายยาวที่มีแต่ป้ายจุดสำคัญ)
- **สายที่คนกรุงเทพขึ้นจริงอ่านรู้เรื่องดี** — พิมพ์สาย 8 (TSB `2-38 (8)`) และสาย 13 (ขสมก. `3-38 (13)`) ทั้งสายออกมาแล้ว **ชื่อครบทุกป้าย** ระบุด้าน/ฝั่งด้วย ("ตรงข้าม…", "ก่อนแยก…", "หลังแยก…", "ทางออก 1/2") ตรงกับที่ CONTEXT.md ต้องการพอดี ส่วนสายรถร่วม DLT อย่าง 1539 อ่านไม่ได้จริง — มีช่วง "จุดขึ้นลง" ติดกัน 7 ป้ายรวด
- **OSM ช่วยได้แค่ 1.5%** — ดึง OSM มา 4,846 node (ตรงกับ ~4,927 ที่ตั๋วอ้าง) แต่ **34.4% เท่านั้นที่มี tag `name`** จับคู่ในระยะ 20 m ได้แค่ **63 ป้ายจาก 4,286 ป้ายไร้ชื่อใน กทม.** (ชื่อไม่ซ้ำจริง 54 ชื่อ) ส่วน POI ใกล้เคียงได้ 17.8% ที่ 100 m แต่ 41% ของชื่อที่ได้คือ "7-Eleven"/ปั๊มน้ำมัน ใช้เป็นชื่อป้ายไม่ได้
- **ไม่มีทางเติมชื่อจากในฟีดเองได้** — `stop_desc` กับ `stop_code` **ไม่มีอยู่ใน stops.txt เลย** ส่วน `zone_id` เป็นสำเนาของ `stop_id` แบบ 1:1 ทั้ง 17,078 แถว และป้ายข้างเคียงก็ช่วยไม่ได้ (ระยะถึงป้ายมีชื่อที่ใกล้ที่สุดบนสายเดียวกัน **median 2.3 กม.**)
- **ข้อเสนอเชิงขอบเขต (ให้ WF-007 ตัดสิน)** — ถ้า MVP จำกัดเฉพาะสาย ขสมก. + TSB ปัญหาป้ายไร้ชื่อ **หายไปทั้งหมด ไม่ต้องเติมชื่อจากแหล่งใดเลย** และยังครอบคลุม 373 สายซึ่งเป็นสายที่มีเลขข้างรถให้เทียบตามกลไกหลักของแอปอยู่แล้ว

**ข้อจำกัดการใช้งาน OSM**
- **สัญญาอนุญาต ODbL** — มีเงื่อนไข share-alike ถ้านำชื่อจาก OSM มารวมกับฐานป้ายของแอปแล้วเผยแพร่
  ฐานผลลัพธ์อาจถือเป็น Derivative Database ต้องเปิดเป็น ODbL ด้วย (แอปนี้ใช้คนเดียว ไม่เผยแพร่ฐานข้อมูล
  จึงไม่ติด แต่ถ้าวันหนึ่งเปิดให้คนอื่นใช้จะกลายเป็นเงื่อนไขทันที) และต้องให้ attribution
- **Overpass เป็น public API ฟรี มี rate limit** (slot 2 ช่องต่อ IP) เหมาะกับดึงครั้งเดียวมาแคช
  ไม่เหมาะเรียกตอน runtime — ระหว่างทำวิจัยนี้ endpoint หลัก `overpass-api.de` ตอบ
  `Dispatcher_Client::request_read_and_idx::timeout` ติดกันหลายครั้งจนต้องย้ายไป `lz4.overpass-api.de`
- **ข้อมูลไม่นิ่ง** — ป้ายใน OSM ถูกแก้ได้ตลอด และ 65.6% ไม่มีชื่อ คุณภาพขึ้นกับอาสาสมัคร

### 3.2 POI / reverse geocode — วัดแล้วเช่นกัน ได้ชื่อที่ใช้ไม่ได้

ดึง POI ที่มีชื่อใน bbox เดียวกันจาก Overpass (วัด ตลาด โรงเรียน โรงพยาบาล มหาวิทยาลัย สถานีตำรวจ
ปั๊มน้ำมัน ห้าง ซูเปอร์ ร้านสะดวกซื้อ สถานีขนส่ง สถานีรถไฟ แยกที่มีชื่อ พื้นที่ค้าปลีก) ได้ **7,328 จุด**

| รัศมีจากป้ายไร้ชื่อ | ครอบคลุม (n=4,286) | ตัวควบคุม: ป้ายมีชื่อ (n=7,234) |
|---|---:|---:|
| 25 m | 2.2% | 8.3% |
| 50 m | 7.3% | 18.4% |
| 100 m | **17.8%** | 37.9% |
| 150 m | 27.0% | 52.6% |
| 250 m | 41.1% | 69.2% |

ดูเผินๆ 17.8% ที่ 100 m ดีกว่า OSM bus_stop มาก **แต่ชื่อที่ได้ใช้ไม่ได้จริง** — วิเคราะห์ 765 คู่ที่ ≤100 m

```
POI ชื่อไม่ซ้ำกันที่ถูกใช้:                       366  (จาก 765 คู่)
ป้ายที่ได้ชื่อซ้ำกับป้ายอื่น:                     478  = 62.5%
ชื่อที่เป็นแบรนด์ร้านสะดวกซื้อ/ปั๊มน้ำมัน:         317  = 41.4%

ชื่อที่ถูกใช้ซ้ำมากที่สุด:
   244 x  "7-Eleven"        <- 244 ป้ายจะได้ชื่อว่า "7-Eleven" เหมือนกันหมด
     9 x  "บางจาก"
     9 x  "PTT"
     7 x  "สะพานใหม่"
     6 x  "Lotus's go fresh"
```

**ชื่อป้ายต้องแยกป้ายออกจากกันได้ ไม่งั้นมันไม่ใช่ชื่อ** ป้าย 244 ป้ายชื่อ "7-Eleven" ตอบคำถาม
"ลงป้ายไหน" ไม่ได้เลย ยิ่งไปกว่านั้นมันยังทำให้ผู้ใช้ **มั่นใจผิดๆ** ว่ารู้ว่าจะลงที่ไหน ซึ่งอันตรายกว่าการบอกตรงๆ
ว่าไม่รู้ ถ้าตัดแบรนด์ทิ้งและเอาเฉพาะชื่อที่ไม่ซ้ำ จะเหลือคู่ที่ใช้ได้จริงราว **250–300 ป้าย ≈ 6–7%**

**ข้อจำกัดของ reverse geocode เชิงบริการ**
- **Nominatim** (ฟรี, ODbL) — นโยบายบังคับ **1 request/วินาที และห้าม bulk geocoding** อย่างชัดเจน
  7,930 ป้าย = 2.2 ชั่วโมงแบบต่อเนื่อง ซึ่งเป็นการใช้งานที่ผิดนโยบาย (ทางที่ถูกคือ self-host หรือใช้ PBF)
- **Google Geocoding API** — คุณภาพดีที่สุดในไทย แต่ **ToS ห้ามเก็บ/แคชผลลัพธ์เกิน 30 วัน** และห้ามนำไป
  สร้างฐานข้อมูลถาวร ซึ่งขัดกับสิ่งที่ต้องการพอดี (ต้องการชื่อป้ายถาวรไว้แคชใน PWA ให้ใช้ตอนเน็ตห่วย)
  โควตาฟรี $200/เดือน ≈ 40,000 request ซึ่งพอสำหรับ 7,930 ป้ายครั้งเดียว — ปัญหาคือ ToS ไม่ใช่โควตา
- **Longdo Map** — ครอบคลุมไทยดี มี free tier แต่ต้องขอ API key และเงื่อนไขการเก็บผลลัพธ์ต้องอ่านก่อน
  (MAP.md จัดไว้ในกลุ่มที่ยังไม่ตัดสินใจอยู่แล้ว)

### 3.3 รูปแบบชื่อที่ฟีดใช้จริง — บอกว่า reverse geocode แบบ POI ตอบไม่ตรงโจทย์

แยกรูปแบบชื่อป้าย 9,148 ป้ายที่มีชื่ออยู่แล้ว (นับซ้อนกันได้)

| ซอย (`ซอยลาดพร้าว 25`) | 1,397 | 15.3% |

ไม่ใช่ POI การเอา POI ที่ใกล้ที่สุดมาตั้งชื่อจึงได้ชื่อคนละประเภทกับที่ฟีดและผู้ใช้คุ้นเคย

## 4. มีอะไรอื่นในฟีดใช้แทนชื่อได้ไหม

**คำตอบสั้น: ไม่มีเลยสักอย่าง**

หัวคอลัมน์จริงของ `stops.txt` มีแค่นี้

```
stop_id,stop_name,stop_lat,stop_lon,zone_id,wheelchair_boarding
```

| ตัวเลือก | ผล |
|---|---|
| `stop_desc` | **ไม่มีคอลัมน์นี้ในฟีด** ตัดทิ้ง |
| `stop_code` | **ไม่มีคอลัมน์นี้ในฟีด** ตัดทิ้ง |
| `zone_id` | มี แต่ `zone_id === stop_id` ครบทั้ง **17,078/17,078 แถว** เป็นสำเนา ไม่มีข้อมูลเพิ่ม (ใช้กับ fare_rules เท่านั้น) |
| `wheelchair_boarding` | ไม่เกี่ยวกับชื่อ |
| `trip_headsign` | มีชื่อจุดหมายปลายทาง ใช้บอก**ทิศ**ได้ (มีประโยชน์กับ MVP) แต่ไม่ช่วยตั้งชื่อป้ายกลางทาง |
| `route_long_name` | รูปแบบ `ต้นทาง - ปลายทาง` ใช้บอกทิศได้เหมือนกัน ไม่ช่วยตั้งชื่อป้าย |

### ชื่อป้ายข้างเคียงช่วยได้ไหม — วัดแล้ว ไม่ช่วย

ระยะจากป้ายไร้ชื่อไปยัง**ป้ายมีชื่อที่ใกล้ที่สุดบนสายเดียวกัน** (n=8,115 instance)

```
p25 = 939 m    median = 2,339 m    p75 = 5,059 m    p90 = 9,218 m    max = 106 km
อยู่ในระยะ 150 m จากป้ายมีชื่อ:  2.8%
อยู่ในระยะ 300 m:                 7.0%
```

ระยะจากป้ายไร้ชื่อไปยัง**ป้ายมีชื่อที่ใกล้ที่สุดในฟีดทั้งหมด** (ไม่จำกัดสาย, n=7,930)

| รัศมี | ครอบคลุม |
|---|---:|
| 20 m | 3.7% |
| 50 m | 7.9% |
| 100 m | 12.8% |
| 200 m | 19.1% |

สรุป: **การตั้งชื่อแบบ "ใกล้ป้าย X" ใช้ไม่ได้** เพราะป้ายไร้ชื่อไม่ได้อยู่ใกล้ป้ายมีชื่อ มันอยู่เป็นดงของตัวเอง
บนถนนที่ไม่มีใครสำรวจป้ายไว้เลย ถ้าจะตั้งชื่อแบบ "ป้ายที่ 5 หลังตลาดปีนัง" ก็จะได้ชื่อที่อ้างจุดที่อยู่ไกล 2 กม.
ซึ่งเป็นคำตอบที่ผิดมากกว่าไม่ตอบ

**หมายเหตุที่เป็นข่าวดี**: ป้ายที่มีชื่อทั้ง 9,148 ป้าย **มีชื่อทั้งไทยและอังกฤษครบ 100%** (รูปแบบ `ไทย;English`)
ไม่มีป้ายไหนที่ขาดฝั่งใดฝั่งหนึ่ง ดังนั้นถ้าจำกัดขอบเขตที่ ขสมก.+TSB ก็ได้ชื่อสองภาษาฟรี

## Confidence and gaps

### มั่นใจสูง (วัดจากไฟล์ตรงๆ ทำซ้ำได้)

- 46.43% (7,930/17,078) และการแยกตาม agency/พื้นที่/route_type/สาย — นับจาก `stops.txt` + `trips.txt` + `stop_times.txt` ทั้งไฟล์ ไม่ได้สุ่ม
- **ขสมก. 0/4,879 และ TSB 0/5,349** — ตัวเลขนี้เป็นศูนย์เป๊ะ ไม่ใช่ปัดเศษ ตรวจซ้ำสองทาง (นับตาม agency ของ trip ที่ผ่านป้าย และดูรายสาย 219+154 สาย unnamed รวม = 0)
- `zone_id === stop_id` ทั้ง 17,078 แถว และ `stops.txt` ไม่มีคอลัมน์ `stop_desc`/`stop_code`
- รายชื่อป้ายทั้ง 3 สายในข้อ 2 — ดึงจาก `stop_times.txt` ตาม `stop_sequence` ของ trip จริง verbatim

### มั่นใจปานกลาง

- **ตัวเลข OSM 1.5%** — พึ่ง snapshot Overpass ครั้งเดียว (2026-09-20) และ bbox สี่เหลี่ยม ถ้า OSM มีการเพิ่มป้ายในอนาคตตัวเลขนี้จะเปลี่ยน แต่ช่องว่างมันกว้างเกินกว่าจะพลิกด้วยการอัปเดตปกติ (ต้องเพิ่มชื่อป้ายหลายพันจุดถึงจะขยับมีนัย)
- **นิยาม "กรุงเทพชั้นใน" = รัศมี 10 กม. จากสยาม** เป็นค่าที่ผมเลือกเอง ไม่ใช่นิยามราชการ ถ้าใช้ขอบเขตวงแหวนรัชดาหรือรายเขต ตัวเลข 17.2% จะขยับ แต่ทิศทาง (ชั้นในดีกว่าชั้นนอกมาก) ไม่เปลี่ยน
- **การนับป้ายตาม agency นับซ้ำได้** — ป้ายหนึ่งที่มีทั้งรถ ขสมก. และรถร่วม DLT ผ่านจะถูกนับทั้งสองแถว ผลรวมคอลัมน์จึงเกิน 17,078 แต่ข้อสรุปหลัก (ป้ายที่มีรถ ขสมก./TSB ผ่าน = ไม่มีไร้ชื่อเลย) ไม่ได้รับผลกระทบ กลับกัน มันแข็งแรงขึ้น เพราะแปลว่าไม่มีป้ายไร้ชื่อแม้แต่จุดเดียวที่มีรถสองเจ้านี้ผ่าน

### ช่องว่างที่ยังไม่ได้ปิด

- **ไม่ได้วัด reverse geocode ของจริง** — ทั้ง Nominatim และ Google ไม่ได้ยิงเลย เพราะ Nominatim ห้าม bulk ตามนโยบาย ส่วน Google ตัดออกด้วยเหตุผล ToS (ห้ามแคชเกิน 30 วัน) ไม่ใช่เพราะวัดแล้วไม่ดี ถ้า WF-007 อยากได้ตัวเลขจริงต้อง self-host Nominatim จาก PBF ของไทย
- **ไม่ได้วัดการเติมชื่อจากชื่อถนน+เลขซอย** — ซึ่งเป็นรูปแบบชื่อ 15.3% ในฟีด และน่าจะเป็นแหล่งที่มีศักยภาพสูงสุดที่ยังไม่ได้ทดสอบ (ต้องดาวน์โหลด road network ของ OSM มาคำนวณระยะถึงเส้นถนน ไม่ใช่ถึง node) ถ้า WF-007 ยังอยากกู้สายรถร่วม นี่คือทางที่ควรลองต่อ ไม่ใช่ POI
- **ไม่ได้ตรวจว่าป้ายไร้ชื่อตรงกับป้ายจริงบนถนนหรือเปล่า** — "visual stop" อาจเป็นจุดที่วาดขึ้นมาเองโดยไม่มีป้ายจริงตั้งอยู่ ถ้าเป็นแบบนั้น การพยายามตั้งชื่อก็ผิดตั้งแต่ต้น ต้องลงพื้นที่หรือดู Street View ถึงจะรู้ — เกี่ยวโยงกับ WF-003 เรื่องความแม่นของพิกัด
- **ไม่ได้ประเมินว่าตัด 943 สาย DLT ออกแล้วเสียอะไร** — รายงานนี้บอกว่า ขสมก.+TSB สะอาด 100% แต่ไม่ได้ตอบว่าเส้นทางที่ผู้ใช้ใช้ประจำจริงๆ พึ่งรถร่วม DLT มากแค่ไหน นั่นคืองานของ WF-007
- **ตัวเลข 0% ของ ขสมก./TSB วัด "มีชื่อ" ไม่ได้วัด "ชื่อถูกต้อง"** — ป้ายมีชื่อครบไม่ได้แปลว่าชื่อตรงกับป้ายจริงที่ตั้งอยู่ริมถนน หรือคนเรียกแบบนั้นจริง ยังไม่ได้ตรวจสอบภาคสนาม
