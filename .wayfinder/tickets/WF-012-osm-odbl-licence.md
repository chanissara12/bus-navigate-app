## Question

ต้นแบบของ [WF-010](WF-010-standing-at-the-stop-screen.md) ใช้ฉากหลังจาก **OpenStreetMap** ซึ่งเป็น **ODbL** ส่วนข้อมูลสายและป้ายมาจากฟีด Namtang ซึ่งเป็น **CC-BY** ([WF-004](WF-004-feed-licence-and-updates.md)) การเอาสองอย่างมาอยู่ในไฟล์เดียวกันแล้วแจกจ่ายมีเงื่อนไขที่ต้องรู้ก่อนจะสร้างทับลงไป

1. **การอบ OSM ลงในแอปนับเป็น Derivative Database หรือ Produced Work** — สองอย่างนี้มีภาระ share-alike ต่างกันมาก ถ้าเป็น Derivative Database ต้องเปิดข้อมูลที่ดัดแปลงแล้วภายใต้ ODbL ด้วย
2. **ต้องให้เครดิตยังไง** — ข้อความและตำแหน่งที่ OSMF กำหนด ต้องโชว์บนแผนที่เลยไหม หรือในหน้าเกี่ยวกับแอปพอ และต้องให้เครดิต สนข. คู่กันยังไง
3. **แอปใช้คนเดียวไม่ได้เผยแพร่ ยังต้องทำตามไหม** — ODbL ผูกกับการ "แจกจ่าย" ถ้าไม่เผยแพร่เลยภาระอาจต่างไป แต่ PWA ที่ deploy ขึ้นเว็บนับเป็นการแจกจ่ายหรือไม่
4. **มีทางเลี่ยงไหม** — มีข้อมูลถนนและแม่น้ำจากแหล่งอื่นที่สัญญาอนุญาตเข้ากันได้ง่ายกว่าไหม เช่น กรมทางหลวง กรมแผนที่ทหาร หรือ Natural Earth (public domain แต่หยาบเกินไปสำหรับระดับเมือง)
5. **ถ้าเปลี่ยนใจไปใช้แผนที่ออนไลน์แทน** — tile server เจ้าไหนที่ ToS ยอมให้แคชเพื่อใช้ออฟไลน์ ซึ่งเป็นเงื่อนไขที่ WF-010 ต้องการ

เขียนรายงานที่ `.wayfinder/research/osm-licence.md`

## Resolution

**เป็น Derivative Database ไม่ใช่ Produced Work — แต่ราคาของการทำตามแทบเป็นศูนย์ จึงทำตามแล้วเดินต่อ**

**1. ทำไมถึงเป็น Derivative Database** — ห่วงโซ่สามขั้นจากเอกสารทางการทั้งหมด: ดึงถนนและสถานที่ราว 5,113 feature ทั่วกรุงเทพแบบเป็นระบบ เข้าข่าย **Substantial** ชัดเจน (เกณฑ์ของ OSMF สรุปเองว่า "village map OK, town map not OK" ต่ำกว่า 100 feature ถึงจะถือว่า insubstantial อัตโนมัติ) · **Douglas-Peucker ไม่ฟอกสัญญาอนุญาต** เพราะ Trivial Transformations Guideline ระบุ "geometric simplifications" การแปลงฟอร์แมต การตัดตาม bbox และการวางป้ายชื่ออัตโนมัติ ว่าเป็น trivial ทั้งหมด ผลลัพธ์ยังเป็นฐานข้อมูล · และบททดสอบ Produced Work มีประโยคเดียวคือ *"ถ้าผลลัพธ์ที่เผยแพร่ตั้งใจให้ดึงข้อมูลต้นฉบับกลับออกมาได้ มันคือฐานข้อมูล ไม่ใช่ Produced Work"* — JSON พิกัดกับชื่อ ดึงกลับได้ตรงๆ ตัวอย่าง Produced Work ในแนวปฏิบัติคือ PNG/JPG/PDF/SVG

**จุดที่กำกวมจริง**: Protomaps แจก vector PMTiles โดยเรียกตัวเองว่า Produced Work แต่ JSON รายการ feature ล้วนๆ อยู่ใกล้ฝั่ง "ฐานข้อมูล" มากกว่า tile format — **ค่าตั้งต้นที่ปลอดภัยคือถือว่าเป็น Derivative Database** เพราะการทำตามมีราคาแค่ลิงก์ดาวน์โหลดหนึ่งลิงก์กับย่อหน้าเครดิตหนึ่งย่อหน้า เดิมพันอีกทางไม่ได้อะไรเพิ่ม

**2. ข้อมูล Namtang ไม่ติด share-alike** — Horizontal Map Layers Guideline ผูก share-alike กับ **ชนิดของ feature ไม่ใช่ชั้นข้อมูล** ตอนนี้ป้ายและสายมาจาก Namtang 100% ถนน แม่น้ำ สถานที่มาจาก OSM 100% ไม่มี feature type ไหนปนกัน จึงเป็น **Collective Database** ซึ่ง ODbL §4.5 ยกเว้นไว้

**ตัวจุดชนวนที่ห้ามแตะ** — ถ้าวันไหนเอา OSM ไปเติมชื่อป้าย (แบบที่ [WF-005](WF-005-unnamed-stops.md) เคยสำรวจ) หรือ snap พิกัดป้ายเข้าถนน OSM หรืออนุมานฝั่งถนนจาก OSM **ชั้นป้ายทั้งชั้นจะถูกดูดเข้า ODbL ทันที** — [WF-003](WF-003-stop-coords-side-of-road.md) ต้องใช้ `shapes.txt` ต่อไปเท่านั้น

**3. เครดิต: หน้า About อย่างเดียวไม่พอ** ต้องอยู่บนหรือติดกับแผนที่ แต่ยุบได้เมื่อผู้ใช้กดปิด เมื่อมี interaction กับแผนที่ หรืออัตโนมัติหลัง 5 วินาที ตราบใดที่ยังมีปุ่ม info กดกลับไปเจอสัญญาอนุญาตได้ — กระทบเฉพาะหน้าแผนที่ของ WF-010 ส่วน CC-BY 4.0 บังคับให้ **ระบุด้วยว่าดัดแปลงอะไร** ซึ่งเคสนี้คือกรองเหลือ ขสมก.+TSB และยุบระเบียนซ้ำ ข้อความที่ใช้ได้จริงทั้งสองแบบอยู่ในรายงาน

**4. URL สาธารณะ = การแจกจ่าย** ODbL นิยาม Convey ว่า "enables a Person to make or receive copies" โดยไม่พูดถึงจำนวนผู้ใช้เลย และ PWA เป็นเคสที่ชัดที่สุดเพราะ service worker ก๊อปปี้ JSON ลงเครื่องผู้เข้าชมโดยตั้งใจ — ใช้บน localhost หรือใส่ auth หน้าเว็บแทบไม่มีภาระ และการใส่ auth ไม่ขัด §4.7 เรื่องต้านมาตรการทางเทคนิค แต่เทียบราคาแล้วทำตามแล้ว deploy คุ้มกว่า

**5. ไม่มีแหล่งทดแทนที่ใช้ได้จริง** — Overture ชั้น transportation/base/divisions/buildings เป็น ODbL ทั้งหมดเพราะ derive จาก OSM · Daylight ก็ ODbL · Natural Earth 1:10m หยาบเกินใช้ในเมือง · RTSD ไม่ใช่ open data · ทางหลวงชนบทบน data.go.th (1:20000, พ.ศ. 2558) ไม่มีโครงข่ายซอย **ชั้นเดียวที่สลับได้จริงคือจุดสถานที่ 1,194 จุด ไปใช้ Overture Places (CDLA-Permissive-2.0)** แต่ถ้าถนนยังเป็น OSM ก็ไม่ได้ลดภาระอะไร เป็นการตัดสินใจเรื่องคุณภาพข้อมูล ไม่ใช่เรื่องสัญญาอนุญาต

**6. เรื่อง tile ยืนยันว่า WF-010 ตัดสินถูก** — `tile.openstreetmap.org` **ห้ามฟีเจอร์ดาวน์โหลดไว้ใช้ออฟไลน์อย่างชัดแจ้ง** · Google ห้ามทุกระดับราคา (place ID เก็บได้ไม่จำกัด แต่พิกัดเก็บได้ 30 วันปฏิทิน) · Mapbox offline ใช้ได้เฉพาะ native SDK เพดาน 6,000 tile ไม่มีทางสำหรับ PWA · MapTiler Cloud ให้แคชชั่วคราวรายเครื่องแต่ห้าม pre-seed · มีแค่ **Stadia Maps** ที่เขียนข้อกำหนดออฟไลน์ไว้ (100 MB ต่อเครื่อง ชั้นฟรีใช้ได้เฉพาะงานไม่แสวงกำไร) และ **Protomaps ที่ self-host เอง** ซึ่งไม่มีข้อจำกัดเพราะกลายเป็นผู้ให้บริการเอง

**ช่องที่ยังไม่ปิด**: ตัวบท DGA Open Government License (มีแต่ PDF จึงไม่ได้ยืนยันว่าเทียบเท่า CC-BY), สัญญาของ MapTiler Server, Mapbox Product Terms, และ Stadia นับ PWA เป็น mobile app หรือไม่
