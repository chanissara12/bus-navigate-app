## Question

นักพัฒนาคนเดียวเข้าถึงตำแหน่งรถเมล์แบบ real-time ในกรุงเทพฯ ได้ไหม และ API เชิงพาณิชย์เจ้าไหนตอบเรื่องรถเมล์ได้ ราคาเท่าไหร่

## Resolution

**ตำแหน่งรถแบบ real-time เข้าถึงไม่ได้เลย** — ไม่มี public API ของ ViaBus (มีแต่ wrapper เถื่อนที่ร้างไปแล้ว `pleum/viabusgo`), ไม่มี GTFS-Realtime ของกรุงเทพฯ ใน Mobility Database, ขสมก. ไม่เปิดตำแหน่งรถ ข้อมูลสดมีอยู่แต่ในแอปผู้ให้บริการที่ล็อก auth ไว้ ดังนั้น **การรอเก้อแก้ด้วยตำแหน่งรถไม่ได้ ต้องแก้เชิงสถิติ**

**Google Directions/Routes โหมด transit ใช้ได้และฟรีพอ** — คืน `line.short_name` (เลขสาย), `departure_stop` และ `arrival_stop` พร้อมชื่อและพิกัด, `num_stops` และที่สำคัญคือ `transit_details.headway` (ระยะห่างระหว่างเที่ยวเป็นวินาที) ซึ่งเป็นตัวแทนที่ดีที่สุดที่หาได้สำหรับการรอเก้อ

**ราคาปี 2026 เปลี่ยนไปแล้ว** — เครดิต 200 ดอลลาร์ต่อเดือนแบบเหมาถูกยกเลิก เปลี่ยนเป็นโควตาฟรีราย SKU: Essentials 10,000 ครั้งต่อเดือน, Pro 5,000 ครั้งต่อเดือน แอปใช้คนเดียวไม่มีทางเสียเงิน

**Longdo Map API ยังไม่ปิดประเด็น** — โควตาฟรี 100,000 transaction ต่อเดือน และ Route API อ้างว่ามีโหมดขนส่งสาธารณะ แต่ **ยังไม่ยืนยันว่าคืนเลขสายและชื่อป้ายหรือคืนแค่เส้น** ถ้าฟีด Namtang ครอบคลุมพอ ประเด็นนี้จะเหลือแค่เรื่อง headway เท่านั้น จึงถูกพักไว้ใน Not yet specified

**ขอบเขตผู้ให้บริการ**: Thai Smile Bus เดินรถ 123 สาย แซง ขสมก. ที่ราว 112 สายไปแล้ว และ ViaBus ไม่มี GPS ของ TSB ทั้งภูมิภาคมีราว 470 สาย 16,321 คัน รวมรถร่วมบริการ minibus และสองแถวซึ่งไม่มีใครทำข้อมูลไว้

รายงานเต็ม: [realtime-and-apis.md](../research/realtime-and-apis.md)

## แก้ไขภายหลัง (จาก WF-013, 2026-09-21)

**ข้อสรุปที่ว่า `headway` ต้องเอาจาก Google นั้นผิด — ฟีด Namtang มี `frequencies.txt` อยู่แล้ว**

ตรวจแล้ว: 10,069 แถวทั้งฟีด โดย 1,776 แถวเป็นของ ขสมก. และ TSB ครอบคลุม **1,369 จาก 1,370 trip (99.9%)** ค่ากลาง headway **15 นาที** p90 60 นาที สูงสุด 240 นาที ช่วงเวลาให้บริการส่วนใหญ่ 05:00-22:00

ตอนทำ WF-002 ไปโฟกัสที่การหา headway จาก API ภายนอกจนไม่ได้เปิดดูไฟล์ในฟีดที่โหลดมาแล้ว

**ผลที่ตามมา**: เหตุผลสุดท้ายที่จะเรียก Google หายไป ข้อสรุปว่า **ไม่เรียก Google เลย** ของ [WF-008](WF-008-destination-lookup-engine.md) จึงยิ่งหนักแน่นขึ้น และการรอเก้อตอบได้แบบออฟไลน์ → [WF-015](WF-015-stalled-wait.md)

ส่วนข้อสรุปหลักของตั๋วนี้ไม่เปลี่ยน: **ตำแหน่งรถแบบ real-time ยังหาไม่ได้อยู่ดี** headway คือค่าที่ตารางบอกว่าควรจะมาทุกกี่นาที ไม่ใช่ว่าคันถัดไปอยู่ตรงไหนจริง
